## 遇到的问题

### 1. 暂存后继续编辑，导致同一个文件出现两个版本

文件执行 `git add` 后，我又继续编辑并保存了学习记录。因此普通 `git diff` 有输出：它显示工作区相对暂存区的新修改，而暂存区仍保留执行 `git add` 时的快照。

当时两个任务文件显示为 `AM`：

- `A` 表示文件已经作为新增内容进入暂存区。
- `M` 表示暂存后，工作区中的同一文件又发生了修改。

### 2. 用 `git status` 判断是否存在提交不够直接

`git status` 能说明当前是否有待提交内容，但检查提交历史是否存在时，`git log` 更直接。仓库还没有首个提交时，`git log` 会提示当前分支没有提交。

### 3. 把“一个提交只做一件事”理解成“只能包含一种文件”

文件类型不同不等于目的不同。README、路线图、学习记录和 `.gitignore` 虽然职责不同，但可以共同完成“建立项目与学习骨架”这一个目的。

## 现在的理解

```text
工作区                  暂存区                   本地仓库
正在编辑的文件  --git add-->  下次提交的快照  --git commit-->  提交历史
```

1. 工作区是磁盘上当前看到和编辑的文件。
2. 暂存区保存已经选入下一次提交的快照。
3. 本地仓库保存在 `.git` 中，包含已经创建的提交历史。
4. `git add` 复制当前文件内容到暂存区，不会创建提交。
5. `git commit` 根据暂存区快照创建提交。
6. `git diff` 比较工作区与暂存区。
7. `git diff --cached` 比较暂存区与当前 `HEAD`；仓库没有首个提交时，暂存内容都会显示为新增。
8. `--stat` 只展示文件和增删行数量摘要；文件处于何种状态应使用 `git status` 查看。
9. 一个清晰提交应围绕一个目的，可以同时包含为该目的服务的不同类型文件。

## 验证证据

- 仓库状态：`git status`
- 选择暂存内容：`git add .gitignore README.md ROADMAP.md docs`
- 工作区相对暂存区：`git diff`
- 暂存区摘要：`git diff --cached --stat`
- 暂存区完整内容：`git diff --cached`
- 实际观察：文件暂存后再次编辑会出现 `AM` 状态
