# 我们怎样边学边做

这个项目不是“我生成代码，你负责运行”，也不是“你先学完课程再开始”。我们采用结对式、证据驱动的学习方式。

## 三种任务归属

### 1. 必须由你先做

- 用自己的话定义需求和验收标准。
- 第一版核心 Agent 循环。
- 解释关键代码和配置。
- 设计最初的评测问题。
- 根据报错提出自己的判断。
- Git 的关键练习和阶段复盘。

我会给概念、提示、最小示例和逐级线索，但不会在你第一次尝试前直接交付完整答案。

### 2. 我们一起做

- 拆分里程碑。
- 设计接口、数据结构和错误处理。
- 调试真实故障。
- 审查代码、测试和安全边界。
- 对比方案并记录技术决策。

### 3. 可以由我代做

- 大量机械性的目录或模板调整。
- 在你已经掌握后重复出现的样板代码。
- 格式化、批量重命名和文档整理。
- 你明确授权的发布辅助工作。

代做不等于黑箱：重要变化仍要说明目的和验证结果。

## 求助阶梯

遇到问题时，按以下顺序推进：

1. 你先描述：期望、实际结果、完整报错、已经尝试过什么。
2. 我先给定位方向或一个提示。
3. 仍然卡住时，我给伪代码或局部示例。
4. 再卡住时，我们一起实现，并由你解释和修改一次。

## “掌握”的验收标准

一个功能能运行还不等于掌握。至少要做到：

- 能说明输入、输出和主要执行路径。
- 能解释关键设计为什么这样选择。
- 能通过测试或实验证明它有效。
- 能处理一个常见错误。
- 能在没有照抄原代码的情况下完成一次小改动。

## 每个里程碑的证据

- 对应的 Issue 或任务说明。
- 小而清晰的提交记录。
- 测试或评测结果。
- 一篇简短学习记录。
- 必要时附架构图、截图或演示。
